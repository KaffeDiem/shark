# Shark design rules

Read this before adding or changing UI. Shark's look is modeled on Linear: a calm, dense, keyboard-first tool where people read for long stretches. If a rule here is wrong for your feature, change the rule here in the same change; don't silently diverge.

## Principles
1. **Reading comes first.** Most time is spent reading transcripts. Contrast, line length and font legibility beat decoration.
2. **Keyboard first.** Every command is reachable from the keyboard and listed in the command palette. The mouse is optional.
3. **Quiet chrome, one accent.** Neutral grays everywhere. Indigo (`primary`) means only three things: keyboard focus, "the agent is running", and the primary button. Status uses icon + text color, never colored fills.
4. **Dark and light are equal.** Every change is checked in both. Never hard-code a color that works in only one mode.
5. **Reuse before building.** Use the gpui-kit component or a pattern already in `src/app.rs` / `src/chat.rs` before writing a new one.

## Agents, tasks, features, and artifacts
- An **agent** (`Agent` in code) is a reusable name, icon, instructions, skills and defaults. Its stable slug links tasks to it; task groups never assign or change that identity. Users start each task by hand.
- A **task** (`Task` in code) is one isolated piece of work. `Task.name` is its immutable internal identity; `Task.title` is its display title. A **harness** runs Claude or Codex for a chat.
- A **task** supplies shared repositories, worktrees, and task context.
- A **feature** is an independent capability that opens an **artifact** in the task tab strip. The Features rail initially contains only **Differ**.
- An **artifact** is the view opened by a capability: an AI chat, the Diff viewer, or a file editor. Its controls, navigation, and view state belong inside it. Diff owns its changed-files tree; a chat owns its transcript, composer, and plan pane.
- The shell owns task navigation, artifact tabs, and feature launchers. Features use shared task services and explicit actions between artifacts, such as sending a review to a chat. Browsing Diff requires neither a loaded chat nor a running agent.
- Keep existing lifecycles: new tasks start with a chat, Differ opens or focuses one Diff artifact per task, and files keep their existing tab behavior. No plugin system or new persistence format is required.

### User stories
1. As a developer reviewing changes, I select Differ and get one Diff tab with both the changed-files tree and the diff.
2. As a developer switching to a chat or file, I see that artifact's controls without the Diff tree; returning to Diff preserves my review position, filter, and folds during the task visit.
3. As a developer returning to review, I select Differ to focus the existing tab or reopen it after closing, without duplicates. Closing a dirty inline editor still requires saving or discarding.
4. As a keyboard user, I open Diff with `cmd-shift-d`, navigate its diff and tree, open files as standalone artifacts, and use `cmd-alt-b` to hide or show only its tree. The toggle does nothing in chats, files, or Home.
5. As a future feature author, I add a launcher and independent artifact using the shared tab lifecycle while keeping its controls inside its artifact.

## Theme
- **Source of truth:** `assets/themes/*.json`, one `ThemeSet` per family with `<Family> Dark` and `<Family> Light`, listed in `THEMES` in `src/settings.rs`. Change colors there, not in Rust. `linear.json` (the default) is hand-tuned; the others are generated by `python3 docs/themes.py` from codigrate palettes, popular editor themes' official palettes and Shark's own, which lifts text colors to the contrast floors below. Edit the palette in the script and regenerate; don't hand-edit generated files.
- **Applying:** `settings::apply` installs the saved light and dark themes with font overrides baked in (a mode switch reloads the config), and `Shark` re-applies it on system appearance changes while the mode is System.
- **The table below lists Linear's values.** Every theme must define the same tokens and meet the same contrast rules.
- **In code:** read colors from `cx.theme()` (`ActiveTheme`). No hex values in views; the only exceptions are the blends `faint()`, `side_hover()` and `side_on()` in `src/app.rs`, because gpui-kit has no token for them.

### Contrast rules
Except for dimmed navigation and file-tree paths, measure APCA (Lc) against **every surface the text can sit on**, including hover and selected rows (`background`, `sidebar`, `secondary`, `muted`, `list_active`, `list_hover`, `sidebar_accent`, `side_hover`, `side_on`, `popover`, `accent`):

| Text | Minimum | Current lowest |
|---|---|---|
| Prose and titles on `background` / cards | Lc 90 | 92.2 dark, 96.2 light |
| Any other readable text: labels, metadata, `muted_foreground`, text in selected/hover rows | Lc 70 | 70.4 dark, 71.4 light |
| Status text and links | Lc 60 | 60.0 dark, 60.1 light |
| Hints (`faint`), never essential | Lc 30 | 33.0 dark, 38.5 light |

Left navigation labels, chevrons and path prefixes use `sidebar_foreground` at **WCAG 2 contrast ≥ 4.5:1** on normal, hover, selected and drop-target backgrounds. Generated themes blend `muted_foreground` 30% toward `sidebar`, then raise contrast to that floor. Navigation rows share these surfaces, so `python3 docs/themes.py` validates every theme, including Linear. The Diff file tree uses `foreground` for folder labels, chevrons and path prefixes on the island background, with `list_hover` and `list_active` row states. This exception does not change the APCA rules for filenames or other text elsewhere.

The displayed destination (Home or task) and keyboard-focused cursor rows use `foreground` for labels and ordinary icons; active/focused task metadata keeps `muted_foreground`. The cursor retains its focus ring, hover keeps its background, and inline naming fields use full foreground. Warning/unread icons and running spinners keep their status colors. Apply foreground colors locally, never whole-row opacity or shared side-row defaults.

Run `python3 docs/contrast.py '<fg>' '<bg>' …` for every new pair. Also: no pure white on near-black, and no font weight below 400.

## Typography
- **UI font:** Inter by default (Settings can swap the UI and code font for any installed font), embedded from `assets/fonts/` (400, 500, 600, 700, italic 400). Use only those weights.
- **Mono font:** JetBrains Mono NL (no ligatures), 400 and 700. **Not inherited:** set `.font_family(theme.mono_font_family.clone()).text_size(theme.mono_font_size)` on code and tool output.
- **Character variants:** `inter_features()` in `src/app.rs` turns on serifed I, tailed l and slashed 0 so paths and hashes are unambiguous. It is applied on the root view and must also be applied to every dialog (`d.font_features(inter_features())`), because dialogs, the palette and notifications render outside the root view.
- **Sizes:** `font.size` is 15 and the window rem equals it:

| Helper | Size | Use for |
|---|---|---|
| `text_xs()` | 11.25px | Metadata, section headers, info rows, status labels |
| `text_sm()` | 13.1px | Default UI: sidebar rows, tabs, buttons, tool rows |
| `text_size(px(14.))` + `line_height(relative(1.5))` | 14px | Transcript prose and user messages |
| `text_base()` | 15px | Empty-state and dialog titles |

- **Weights:** 400 for text; `FontWeight::MEDIUM` for emphasis (active sidebar item, tool names, section headers); `SEMIBOLD` for markdown headings only.
- Sentence case for labels, headers and menu items ("Tasks", not "TASKS"; "Copy branch name", not "Copy Branch Name"). Proper nouns keep their capitals ("Reveal in Finder"). The macOS menu bar is the one exception: it uses Title Case, as every Mac app does.
- **Line length:** prose sits in a centered `max_w(px(680.))` column (~70 characters). The composer card is `max_w(px(712.))`.

## Layout
- **Inverted L:** the sidebar and the window's top edge share `sidebar`. Content sits in one island: below a 44px titlebar, inset 8px right and bottom, `rounded(theme.radius_lg)`, 1px `border`, `bg(background)`, `overflow_hidden()`.
- **Tabs:** each tab reserves space for its close button, revealed only by hovering that tab, even in an unfocused window. Background closure preserves view and focus. Diff closure persists per task; explicit Diff actions reopen it and navigation counts only visible tabs.
- **Titlebar:** transparent. The 44px top row reserves the first 80px for the traffic lights; the sidebar toggle follows at x80 in both sidebar modes. Only unused space is draggable, so tab drags and buttons keep their mouse events.
- **Settings dialog:** 800px, a 168px left nav of `ghost` `small` buttons (General, Appearance, Prompts; `ctrl-tab` cycles them), the selected one `selected`. A page is `section()` headers over `card()`s. Settings are rows inside a `secondary` card: label `text_sm` plus a `text_xs` `muted_foreground` description on the left, a 240px control on the right, 1px `border` between rows. Changes apply immediately; there is no Save button. Multi-choice settings use a `Select` (or the mode pills for System/Light/Dark). Licenses and attributions live in the About dialog, not in a settings page.
- **Where a new view goes:**
  - A view of the open task is an artifact in a header tab. Reuse the existing tab lifecycle; add a tab kind only for a new artifact.
  - Home, All tasks and agent pages are overview destinations in the central area, reached directly from the sidebar. Configuration (settings, repo list) opens with `window.open_dialog`, `w(px(640.))`, like the palette.
  - Repos are set up once, so they sit in Settings › Repositories (`ReposPage`, `src/app/repo_settings.rs`), after Sentry's and Cofounder's Repositories pages on Mobbin, not in the sidebar. A row opens repo settings as a dialog over Settings. Anything that leaves for a task closes both.
  - Artifact-specific panes stay inside their artifact. The file editor fills the central area; Chat remains available through its tabs and shortcuts. The file tree belongs only to Diff, inside the island.
- **Side rows** (`side_row` in `src/app.rs`, left navigation, after Linear's sidebar): 30px tall plus 2px below (a 32px pitch), `mx_2`, a 1px transparent border and 7px padding so icons start 16px from the pane edge, `gap_2`, `rounded(theme.radius)`, `text_sm` in `muted_foreground`. `cursor_row` sets the state: the open item gets `side_on` and `foreground`, other rows `side_hover` on hover. Order: icon (16px), name (`flex_1`, truncated), optional badge, metadata or count (`text_xs`, `muted_foreground`, right-aligned). Group headers (`side_header`): `px_4 pt_4 pb_1`, `text_xs` `MEDIUM` `muted_foreground`; a header's button shows on hover. Sidebar width 244px.
  - Task rows are 44px with two lines: the name, then its repos (`text_xs`, `muted_foreground`, `api · web`), so you can see where a task works without opening it. The open task has the pill.
- **Task groups:** optional grouping in All tasks, independent of agent identity. The grouping control switches status buckets to plain sections (`Section.agent == None`) plus Ungrouped; every task remains visible. Task groups… offers creation and management, including empty groups. Rename uses a dialog; icon and delete use shared menus. Group edits and moves never change `Task.agent`. Legacy agent-bound sections remain persisted but are not used for grouping or assignment.
- **Zen mode:** `cmd-.`, View › Toggle Zen Mode or the palette shows only the shown tab (chat, Diff, Git or file) on the island `background`: no sidebar, titlebar tabs, task header or Features rail. A 44px bar keeps the traffic lights clear, drags the window and holds the tab's own controls (Diff's comparison toolbar). Every shortcut keeps working, so tabs switch within Zen; `cmd-alt-←/→` walks only the shown panes. `cmd-b` (asking for the sidebar), Home or `cmd-.` again ends it. Session-only.
- **Sidebar rail:** `cmd-b` shrinks the sidebar to a 72px rail with 32px icon buttons and tooltips; opening, selecting, and closing files preserve the sidebar’s current state. The toggle moves into the titlebar at the same window position, followed by Commands and New task. Expanded, Commands and New task sit to the right of the content-sized Home button, with a 4px gap between them. Commands uses the Command icon and the “Commands (cmd-k)” tooltip and accessibility label. Home shows its `cmd-0` hint only while Command alone is held. Both create buttons run the existing `cmd-n` action.
- **Features rail:** fixed at 72px on `sidebar`, beside every task artifact and absent on Home. Its only item is Differ, using `rail_button`, a tooltip, and an accessible name. It opens or focuses the single Diff artifact; the pill marks that artifact active. Keep the unviewed/error indicator. The rail has no expansion toggle, resize handle, Commands item, file tree, or artifact-specific context menu; retain the 44px titlebar spacing and align the launcher’s top with Home in both expanded and collapsed sidebar layouts. Pane navigation reaches the launcher; Enter activates it.
- **Diff file tree:** a column on the right inside Diff, on the island `background`, below the artifact-wide comparison toolbar. The toolbar wraps at narrow widths; diff content is clipped to its own column. It is shown by default, hidden with **Files** or `cmd-alt-b` while Diff is active, and resizes from 200–560px with a 244px default; keep the saved width. Visibility is session-only. It is absent from chat/file artifacts and their keyboard focus order. Hiding it while the tree or filter has focus returns focus to Diff. Its `Files` header uses `side_header` styling with a viewed count. Keep 30px rows indented 12px per level, 16px icons and 14px folder chevrons. Use `list_cursor_row` for island hover/selection/focus states. The viewed checkbox also works on folders. Folders come first; single-child folders are joined.
  - Draw decorative 1px vertical guides in `border` at each ancestor's chevron center, from beneath its folder row to the center of its last visible descendant; no horizontal branches. Derive each virtualized row's segments from its depth and the next visible row's depth, including after filtering or folding.
  - Folder labels, chevrons, and compact file prefixes through the final `/` use `foreground` on the island background. Filenames keep their viewed color and open-file weight; status dots, counts, checkboxes, selection backgrounds and focus rings keep their existing treatment. Never dim a whole row.
- **Toolbar controls:** `ui::toolbar(id, button)` styles the existing house button, retaining its actions, tooltips, keyboard focus, disabled/loading states and accessibility. Use it after configuring the button, with the same ID. `ui::quiet_toolbar` is the same control with no fill or border at rest, for the sidebar's and rail's chrome icons and the tab strip's +; `secondary_hover` fades in on hover, press and keyboard focus, but a mouse click's focus does not hold it. Default geometry is 32px tall, 16px icons and capsule corners; explicit geometry remains available for split controls and tight chrome. Icon-only actions are circular; labeled controls (including Plan, Fast and Model in the composer) are capsules. Keep primary/destructive actions prominent and inline close/copy controls compact.
  - Idle controls use a local muted foreground and subtle neutral fill/border. Hover brightens them over 120ms; pressing, keyboard focus and selected/open states respond immediately. Theme-derived colors work in dark/light families without dimming body text. Idle toolbar labels follow the WCAG 4.5:1 control contrast floor (all 42 bundled variants checked; lowest 4.63:1), rather than the APCA body-text floor. Reduced motion resolves immediately. Menu triggers remain surfaced until dismissed.
  - Reference: the supplied Linear screenshots (144dpi, interpreted at 2×) show ~32px circles, 16px glyphs, ~7px gaps and 14px menu corners. [Linear's 2026 design account](https://linear.app/now/behind-the-latest-design-refresh) supports the calmer, consistent controls; [Emil Kowalski's motion guidance](https://emilkowal.ski/ui/you-dont-need-animations) supports fast feedback and immediate keyboard interactions. The 120ms timing is Shark's choice, not a measurement from the still screenshots.
- **Menus** (right-click menus and dropdowns, not the menu bar): `src/menu.rs`, drawn after Linear's menus (gpui-kit's `PopupMenu` hard-codes 26px rows, 2px separators and full-colour icons). Right-click on sidebar rows opens one at the mouse. A dropdown hangs from the button that opens it (`menu::open_at` with the anchor corner): the git menu under its chevron, the model menu above the composer's model button (also cmd-/; Claude's models, a separator, then Codex's, with a hint naming the backend where the label doesn't), each starting on the current choice. Typing letters jumps to the row that starts with them, as in a Mac menu. The composer's completions use the same `menu::chrome` and `menu::highlight`.
  - `popover` surface, 14px corners, `p(6px)`, measured from contents and normally 200–440px wide, constrained to an 8px window margin. Keep the 14% dark / 10% light `foreground` ring plus soft shadow instead of a border. Action labels, hints and completion popups use 14px type; hints use `muted_foreground`.
  - 36px action and completion rows (`menu::ROW_H`), 13px separator blocks (49px between separated action centers), `px(10px) gap(10px)`, highlight an inset 8px `theme.radius` pill in 7% `foreground`; the text color doesn't change. Mouse and arrow keys share one highlight.
  - Action labels take priority over hints; fixed icon, check and chevron slots stay outside the text. Hints yield their space first. Overflowing text uses the tabs' 24px fade into the actual row background, with the full clipped label and hint in a tooltip. Labels only clip when the window forces it; intentional ellipses in action names stay intact.
  - Submenus use the rendered parent's bounds: open right when they fit, otherwise left, otherwise use the roomier side, leaving a traversable 4px gap and an 8px window margin. Hover protection follows the opening direction. If neither side has 200px, click or keyboard activation replaces the parent with the submenu; hover only highlights. A Back row, Left or Escape returns to the parent's selection and scroll position.
  - Panels scroll when their contents exceed the viewport. Keyboard navigation keeps the selected row visible; scrolling a parent closes its adjacent child. Escape dismisses the root menu, restores focus, and an outside click dismisses without activating the content underneath.
  - 16px icons in muted foreground (dark mode blends 61% foreground over the popover; app icons 18px); separators are 1px, full width, 6px space above and below.
  - No header row: say what an item acts on with a right-aligned muted hint instead (the branch on `Copy Branch Name`, the `~/…` path on each path row).
  - At most three groups: open/reveal (`Reveal in Finder`, then `Open in <app>` for each app LaunchServices lists for folders (`src/apps.rs`) with the app's own icon, then `Copy path`; each a submenu with "Task folder" plus one row per repo, or a plain item with its target as the hint when there's only one. Git clients list only the repos, Xcode only the repos' projects and hides when there are none; a repo row's menu has the same items for that repo), then git (`Open pull requests`, hidden when there are none), then destructive (`Delete task`, `Force delete task…`) last, in normal text like Linear's Delete.
  - The current choice or a setting that's on gets `.checked(true)`: a 16px `Check` in `muted_foreground` at the right end (never a `✓` hint).
  - Hide items that don't apply instead of disabling them. No shortcuts in these menus; every item also exists in the palette, which shows them.
  - Sentence case labels; an ellipsis only when the item opens a picker or asks for confirmation.
- **Git menu:** the chevron next to the git button. Groups: the next step (hint "Next"), then sync (Fetch now, Commit and push, Pull, Push, Update from base; agent prompts have a "Queue" hint), then PRs (Create or update, Create draft, Merge PRs… and Open PRs in browser while a PR is open, and with more than one repo a Merge order submenu, the order as its hint, holding each repo's possible moves (Merge web earlier, Merge api later)), then the "Delete remote branches after merge" setting, checked while on. Repo states and errors stay in the git button's tooltip, not as rows that do nothing.
- **Dialogs:** shared `ui::dialog` / `ui::alert_dialog` use 14px corners, 20px content padding and compact 14px base text. Native 180ms fades keep hit targets still and respect reduced motion. Menu dialogs override the form padding with the menu surface's 6px inset. Native Select controls use medium sizing; their popup shells and editor language-service popovers remain library-drawn because gpui-kit exposes no popup-style override.
- **Command palette** (`cmd-k`, `src/app/palette.rs`): gpui-kit's `Command` through `ui::command` in `menu_dialog`: 36px native rows, compact native small text, 6px outer inset and the same 14px corners, popover surface and shadow as click menus. Each `COMMANDS` row is a `Row(label, icon, action, keywords, handler)`: the handler runs it; the action is only read for its shortcut, shown right-aligned in `muted_foreground` (the newest one-key binding valid where the palette was opened, never a Vim-only key). Keywords are extra words the filter matches. Rows are grouped under headings (`GROUPS` names each group by its first row): Task, Chat, Plan, Files and diff, Git, Task groups, View, Shark, then Open task with one row per task, in sidebar order. Rows only one backend can do are left out for the other: `CLAUDE_ONLY` (side question) while the shown chat runs Codex, `CODEX_ONLY` (fast mode) otherwise. `NEED_LINEAR` rows are left out while nobody uses Linear. Pickers that aren't tied to a button (section, icon, merge order from cmd-k, reopen chat, repository attachment actions, Show attachments) go through `open_menu` or `open_grouped`, with a placeholder that says what they pick, and look the same. Show attachments groups Repositories and Linear issues, each row with its status mark and in words.
- **Menu bar** (`src/menubar.rs`): items dispatch existing actions, so their shortcuts come from the keymap. Every Shark command in it also exists in the palette; the macOS standard items (Hide, Quit, Minimize, Zoom, Services, Edit) don't need to. Nor do Help's two links (README, Report an Issue); its Keyboard Shortcuts item opens the palette, which shows each command's shortcut. Edit uses gpui-kit's input actions with an `os_action`, so it works in any text field.
- **Header:** repository, attachment-state, Linear issue and overflow controls are 32px toolbar buttons with keyboard activation and preserved status colors. Repository dropdowns hang 4px below their button on click or keyboard activation; right-click opens at the pointer. The 44px titlebar sits above the island, with 4px gaps between tabs. Inside the island, a 44px header with 16px horizontal padding and `border_b_1` holds repository/branch and Linear attachment chips on the left and the git button (`src/sync/`) on the right.
- **Attach:** one 32px toolbar capsule (`header-attach`, `Paperclip`) after the attachment chips, the only place in the header to start an attachment. With Linear in use it has a caret and opens a two-row dropdown (Repository…, Linear issue…) 4px under the button, first row highlighted; without, it opens the repository dialog directly. The two dialogs stay separate, each with its own `cmd-k` row: a repository is a local form queued behind idle, an issue a remote search that works mid-turn. It gives up its label before chips get hidden. Both dialogs are 640px with 36px rows, search first with no title, and `ui::key_footer` for their keys (`enter` attach, `cmd-enter` mark) with a count on the right. With marks, `enter` and the footer's Attach attach exactly the marks.
- **Linear stays out of the way:** `Shark::linear_in_use` (connected in any state, or an issue attached to any task) gates everything Linear shows outside Settings: the Attach dropdown, Home's Start from Linear issue, `NEED_LINEAR` rows, and Attach Linear issue in Show attachments. Delete task goes by that task's issues. Settings › Linear and the manual always stay. Don't add a "connect Linear" prompt elsewhere.
- **Run button:** left of the attachment chips, a 32px circular toolbar button (id `run`): `Play` when idle (tooltip "Run (cmd-r)"), `Square` while the run scripts run (tooltip "Stop (cmd-r)"), with a `text_xs` `success_foreground` `Running :<port>` label beside it. Right-click: Run/Stop, Show script output, Edit run scripts….
- **Repository chips:** one status mark and the repository name per attachment, with no caret, like issue chips. `repo · branch` appears only when the checkout differs from the attached branch, including Detached HEAD, at most 280px wide with truncation. The accessible label and hover card expose branch, base, worktree path and stack details. The checked-out branch is used after a successful probe; saved branch data is the fallback before probing or on error.
- **Chip hover cards:** repository, pending and issue chips use `ChipCard` (`src/app/attach.rs`) instead of a tooltip: `menu::chrome`, 240–440px wide, hanging 4px under the chip's left edge like its menu. A status mark and medium title lead a property list after Linear's Properties panel: an 88px `muted_foreground` label column, then a wrapping value. The card stays away while a menu or dialog is up, because popups paint above both. It is only a preview: what a click opens carries every fact, so nothing needs a pointer. A repository's menu leads with its pull request (Create pull request while it has none, or Open pull request with a `#124 · Open` hint and Merge pull request…, then Open branch on GitHub), then stack rows, then branch rows, then Reveal in Finder, Open in <app> and Copy path. It says the card's facts as hints on rows that act on them (Copy branch name, Copy path, Change base…, Copy Git error, stack rows); issue details and the attachment panel already do. Ready chips open their repository menu on either click or keyboard activation; pending/failed chips open attachment recovery. Failure-first overflow and `+N` also keep hidden repositories reachable.
- **Repository branch menu:** the selected repository’s stack rows (newest first), rebase action, Copy branch name, Change base…, and GitHub/PR links. Every action targets that repository; the GitHub link explicitly identifies the attached branch when checkout differs. New task on top… and Insert task below… stay in the task menu and cmd-k, alongside task-wide branch operations. “Branch menu…” in cmd-k opens the sole repository directly, or a repository picker when several are attached; it also works with the header hidden.
- **Git button:** a `small` button plus a `ghost` `xsmall` chevron for the git menu. It is the header's one primary button: `primary` for a step to run, `outline` with a `warning_foreground` icon when something needs the agent or a human, `ghost` for a wait. ## Interaction states
- **Focus:**
  - Focused list row: in the side panes the `side_on` pill plus a 1px `primary` border, shown only while the pane has focus (no indigo fill); inside the island `list_active` plus a 1px `primary` border, or a 2px `primary` left bar (transcript). The tint alone is not visible enough.
  - Inputs and buttons use gpui-kit's `ring`.
- **Hover:** a background step (`list_hover` / `side_hover` / `secondary_hover`) or, for tabs, text color. Never the only way to discover something.
- **Disabled:** `muted_foreground` text and the component's `.disabled(true)`; no hover; not focusable.
- **Motion:** use `Spinner` and gpui-kit's built-ins. During reordering, constrain tabs to horizontal movement inside their strip and sidebar rows to vertical movement inside their pane; animate neighboring items live with gpui-kit's motion support and respect reduced motion. Toolbar hover and action-menu fades take 120ms; dialogs and command palettes use the native 180ms `DialogEntrance::Fade`, without moving their hit targets. Reduced motion skips these transitions.
- **Selection:** text selection is translucent indigo (`selection.background`); keep it translucent so selected text stays readable.

## Copy buttons
- **Never move anything.** A hover-revealed button is `invisible()` until its group is hovered, so its slot is always laid out. Showing it, and the check after a copy, changes no size.
- **Never cover text.** Content reserves the corner the button sits in: the user card's text column stops before it, tool output has `pr_8`, code blocks keep the 28px top padding the language label had.
- **Where:** user messages top-right of the card; a reply on its closing line ("done · 48s", always shown on the latest reply); code blocks and tool output in their top-right corner; the plan pane and side-question card in the header before ×, always shown.
- Hover is never the only way: `y` copies the selected transcript row or the shown plan, `c` the side answer, and the palette has "Copy selected message" and "Copy plan".

## Copy and destructive actions
- **Confirm only when data is lost.** Delete task and force delete both confirm: they remove conversations and plans.
- **Confirm dialogs:**
  - Title `Verb {name}?`.
  - The description states the consequence.
  - `ok_text` is the verb; use `show_cancel(true)`.
- **Errors name the fix**, including the key or the palette command: "Add a repo first (Add repo in cmd-k)".
- **Progress notifications** end with an ellipsis: "Creating PRs…".

## Keyboard and focus
- **Focus handling:** every view that handles keys gets a `key_context(..)` and a `FocusHandle`.
- **Bindings** go in `bind_keys` in `src/main.rs`. There are no `space` leader chords: a command without a key is found in `cmd-k`.
  - **Vim mode** (Settings › General, `ctrl-cmd-v`, `State::vim`) is one switch for the editor, the composer and the lists. While it's on the root view carries the `Vim` key context; Vim-style keys (`j/k`, `gg`, `G`, `ctrl-d/u`, `h/l`, `g t`, `]c`/`[c`, the queue's `shift-j/k`) are bound with the `vim(..)` helper under `Vim > (…)`, and `ctrl-w h/l` under `Vim`. Each has a non-Vim key that always works: the arrows, `home`/`end` and `pageup`/`pagedown` in lists (`ARROWS`), `←/→` to fold and switch plan versions, `alt-↑/↓` for changes and queue order, `cmd-alt-←/→` for panes. `Shark::set_vim` applies a change everywhere at once.
  - For lists, add the context to `LIST`, `MOVE` and `ARROWS`, and handle `SelectNext/Prev/First/Last/Confirm`, plus `PageDown/PageUp` where the list scrolls. The sidebar currently doesn't handle `PageDown/PageUp`.
- **New global commands** need:
  - an `actions!` entry;
  - a `COMMANDS` row with its action and keywords;
  - a menu-bar item where it fits;
  - a direct shortcut only when it's used often; otherwise the palette is the way in;
  - a line in the keys table in docs/manual.md.
- **Row actions** act on the cursor row of the focused list, otherwise on the open item (see `archive`). They get a single-key binding in the list's context plus a palette row.

## Gotchas
- **Unknown theme keys are silently ignored.** Copy key names from `ThemeConfigColors` in gpui-component's `theme/schema.rs` (the link color is `link`, not `link.foreground`). The `themes_parse` test checks the core keys; extend it when you rely on a new one.
- **`list.active.background` alpha is capped at 20%** by gpui-kit. Setting a higher alpha does nothing.
- **The `tab.*` theme keys are unused;** tabs use `background` / `secondary` / `secondary_hover` and `foreground` / `muted_foreground`.
- **`cx.theme()` borrows `cx`.** Copy the colors you need into locals before calling `cx.listener(..)` or other `&mut cx` methods (see the composer in `src/chat.rs`). Don't clone the whole `Theme` per render.

## Checklist for a UI change
1. Colors come from theme tokens (or `faint`), with no hex in views. Every new text pair meets the contrast rules.
2. Sizes, radii, type and icons come from the tables above. Status uses the status vocabulary.
3. The command is reachable by keyboard and listed in the palette and the keys table in docs/manual.md.
4. Dialogs apply `inter_features()`.
5. `cargo test --features test-support` passes (the headless keyboard test covers focus and key contexts).
6. Checked by eye in both modes, without changing the system appearance:
   ```sh
   ./target/debug/shark &                                         # follows the system (dark here)
   ./target/debug/shark -NSRequiresAquaSystemAppearance YES &     # forces light for this process
   screencapture -x -o -l <window-id> .context/shot.png           # window id: CGWindowListCopyWindowInfo, owner PID
   ```

Sources: Linear's app code and design posts ("How we redesigned the Linear UI", "Behind the latest design refresh"), APCA, Wallace et al. 2022 on font legibility.

### Task quick open

- `cmd-shift-o`, File → Open task…, and the command palette open the dedicated picker in `src/app/task_picker.rs`. While the `cmd-o` app switcher is open, this shortcut still reverses its selection. Releasing Command never confirms the task picker.
- Reuse `CommandState`, custom variable-height `CommandItem` rows, and the 640px `menu_dialog` surface, constrained to the viewport. Focus search immediately; arrows navigate, Enter/click opens, one Escape dismisses and restores focus. Footer: `↑↓ Navigate · ↵ Open · Esc Close`.
- Include every live task, regardless of task grouping. Score task and each repository name separately with the completion matcher, treating spaces, hyphens, underscores, slashes and dots as word separators, taking the best score, then recorded interaction recency, then sidebar order. With no query, select the most recent other task (most recent from Home). Query changes select the best match; background status updates preserve order and selected identity.
- Each row shows the task name, Current when applicable, last user interaction with its exact time in a tooltip, and one compact line per repo. Show explicit Draft/Open/Merged/Closed/No PR/Not checked/Status unavailable labels from `overview_repos`; failing checks never hide Draft. Full names and statuses have accessible labels and overflow tooltips. Empty states distinguish no tasks from no matches.
- A fixed 16px status icon precedes the name, shared with the sidebar: the primary `LoaderCircle` spinner while a task runs, otherwise warning `CircleAlert` for needs-you, success `CircleCheck` for unread, or muted `CircleDashed` for idle. Details align below the name with an 8px gap after the icon. A compact `text_xs` line shows the running-chat count, needs-you action, or Unread; retain a needs-you action alongside the count when another chat runs. Idle has no extra line. Only running agents animate; Git checks keep static icons. Status updates preserve the query, result order, and selected task.
- `Task.last_interacted_at` stores optional Unix milliseconds. Successful explicit navigation and keyboard/click/scroll activity in visible task content count; Home, picker browsing, startup restore, activation, agent output and polling do not. Successful task dialog actions count. Coalesce recency saves once per second and flush through the close/quit storage guard. Unknown timestamps sort last and display No recorded interaction.
- Confirm destinations by name and resolve them again after unsaved-edit confirmation, before changing any buffers. Removed destinations and ones being deleted preserve the current edits. Opening the current task preserves its view; canceled confirmation never records destination recency.

## Persistent agents

`state::Agent` stores a stable slug, display identity, instructions, repository/model defaults and capped task history. Each `Task` carries an `AgentLink` snapshot so harness startup, root docs and context delivery do not depend on global state. Tasks retain separate worktrees and branches under the existing `~/shark/workspaces` path. `Shark::sync_agent` refreshes snapshots and publishes them to loaded chats; root docs and harness skill links refresh on dialog close. Skill sources are harness-neutral under the support directory.
