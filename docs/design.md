# Shark design rules

Read this before adding or changing UI. Shark's look is modeled on Linear: a calm, dense, keyboard-first tool where people read for long stretches. If a rule here is wrong for your feature, change the rule here in the same change; don't silently diverge.

## Principles
1. **Reading comes first.** Most time is spent reading transcripts. Contrast, line length and font legibility beat decoration.
2. **Keyboard first.** Every command is reachable from the keyboard and listed in the command palette. The mouse is optional.
3. **Quiet chrome, one accent.** Neutral grays everywhere. Indigo (`primary`) means only three things: keyboard focus, "the agent is running", and the primary button. Status uses icon + text color, never colored fills.
4. **Dark and light are equal.** Every change is checked in both. Never hard-code a color that works in only one mode.
5. **Reuse before building.** Use the gpui-kit component or a pattern already in `src/app.rs` / `src/chat.rs` before writing a new one.

## Workspaces, features, and artifacts
- A **workspace** supplies shared repositories, worktrees, and task context.
- A **feature** is an independent capability that opens an **artifact** in the workspace tab strip. The Features rail initially contains only **Differ**.
- An **artifact** is the view opened by a capability: an AI chat, the Diff viewer, or a file editor. Its controls, navigation, and view state belong inside it. Diff owns its changed-files tree; a chat owns its transcript, composer, and plan pane.
- The shell owns workspace navigation, artifact tabs, and feature launchers. Features use shared workspace services and explicit actions between artifacts, such as sending a review to a chat. Browsing Diff requires neither a loaded chat nor a running agent.
- Keep existing lifecycles: new workspaces start with a chat, Differ opens or focuses one Diff artifact per workspace, and files keep their existing tab behavior. No plugin system or new persistence format is required.

### User stories
1. As a developer reviewing changes, I select Differ and get one Diff tab with both the changed-files tree and the diff.
2. As a developer switching to a chat or file, I see that artifact's controls without the Diff tree; returning to Diff preserves my review position, filter, and folds during the workspace visit.
3. As a developer returning to review, I select Differ to focus the existing tab or reopen it after closing, without duplicates. Closing a dirty inline editor still requires saving or discarding.
4. As a keyboard user, I open Diff with `cmd-shift-d`, navigate its diff and tree, open files as standalone artifacts, and use `cmd-alt-b` to hide or show only its tree. The toggle does nothing in chats, files, or Home.
5. As a future feature author, I add a launcher and independent artifact using the shared tab lifecycle while keeping its controls inside its artifact.

## Theme
- **Source of truth:** `assets/themes/*.json`, one `ThemeSet` per family with `<Family> Dark` and `<Family> Light`, listed in `THEMES` in `src/settings.rs`. Change colors there, not in Rust. `linear.json` (the default) is hand-tuned; the others are generated by `python3 docs/themes.py` from codigrate palettes, popular editor themes' official palettes and Shark's own, which lifts text colors to the contrast floors below. Edit the palette in the script and regenerate; don't hand-edit generated files.
- **Applying:** `settings::apply` installs the saved light and dark themes with font overrides baked in (a mode switch reloads the config), and `Shark` re-applies it on system appearance changes while the mode is System.
- **The table below lists Linear's values.** Every theme must define the same tokens and meet the same contrast rules.
- **In code:** read colors from `cx.theme()` (`ActiveTheme`). No hex values in views; the only exceptions are the blends `faint()`, `side_hover()` and `side_on()` in `src/app.rs`, because gpui-kit has no token for them.

### Contrast rules
Except for dimmed navigation and file-tree paths, measure APCA (Lc) against **every surface the text can sit on**, including hover and selected rows (`background`, `sidebar`, `secondary`, `muted`, `list_active`, `list_hover`, `sidebar_accent`, `side_hover`, `side_on`, `popover`, `accent`):

| Text | Minimum | Current lowest |
|---|---|---|
| Prose and titles on `background` / cards | Lc 90 | 92.2 dark, 96.2 light |
| Any other readable text: labels, metadata, `muted_foreground`, text in selected/hover rows | Lc 70 | 70.4 dark, 71.4 light |
| Status text and links | Lc 60 | 60.0 dark, 60.1 light |
| Hints (`faint`), never essential | Lc 30 | 33.0 dark, 38.5 light |

Left navigation labels, chevrons and path prefixes use `sidebar_foreground` at **WCAG 2 contrast ≥ 4.5:1** on normal, hover, selected and drop-target backgrounds. Generated themes blend `muted_foreground` 30% toward `sidebar`, then raise contrast to that floor. Navigation rows share these surfaces, so `python3 docs/themes.py` validates every theme, including Linear. The Diff file tree uses `foreground` for folder labels, chevrons and path prefixes on the island background, with `list_hover` and `list_active` row states. This exception does not change the APCA rules for filenames or other text elsewhere.

The displayed destination (Home or workspace) and keyboard-focused cursor rows use `foreground` for labels and ordinary icons; active/focused workspace metadata keeps `muted_foreground`. The cursor retains its focus ring, hover keeps its background, and inline naming fields use full foreground. Warning/unread icons and running spinners keep their status colors. Apply foreground colors locally, never whole-row opacity or shared side-row defaults.

Run `python3 docs/contrast.py '<fg>' '<bg>' …` for every new pair. Also: no pure white on near-black, and no font weight below 400.

## Typography
- **UI font:** Inter by default (Settings can swap the UI and code font for any installed font), embedded from `assets/fonts/` (400, 500, 600, 700, italic 400). Use only those weights.
- **Mono font:** JetBrains Mono NL (no ligatures), 400 and 700. **Not inherited:** set `.font_family(theme.mono_font_family.clone()).text_size(theme.mono_font_size)` on code and tool output.
- **Character variants:** `inter_features()` in `src/app.rs` turns on serifed I, tailed l and slashed 0 so paths and hashes are unambiguous. It is applied on the root view and must also be applied to every dialog (`d.font_features(inter_features())`), because dialogs, the palette and notifications render outside the root view.
- **Sizes:** `font.size` is 15 and the window rem equals it:

| Helper | Size | Use for |
|---|---|---|
| `text_xs()` | 11.25px | Metadata, section headers, info rows, status labels |
| `text_sm()` | 13.1px | Default UI: sidebar rows, tabs, buttons, tool rows |
| `text_size(px(14.))` + `line_height(relative(1.5))` | 14px | Transcript prose and user messages |
| `text_base()` | 15px | Empty-state and dialog titles |

- **Weights:** 400 for text; `FontWeight::MEDIUM` for emphasis (active sidebar item, tool names, section headers); `SEMIBOLD` for markdown headings only.
- Sentence case for labels, headers and menu items ("Workspaces", not "WORKSPACES"; "Copy branch name", not "Copy Branch Name"). Proper nouns keep their capitals ("Reveal in Finder"). The macOS menu bar is the one exception: it uses Title Case, as every Mac app does.
- **Line length:** prose sits in a centered `max_w(px(680.))` column (~70 characters). The composer card is `max_w(px(712.))`.

## Layout
- **Inverted L:** the sidebar and the window's top edge share `sidebar`. Content sits in one island: below a 44px titlebar, inset 8px right and bottom, `rounded(theme.radius_lg)`, 1px `border`, `bg(background)`, `overflow_hidden()`.
- **Tabs:** each tab reserves space for its close button, revealed only by hovering that tab, even in an unfocused window. Background closure preserves view and focus. Diff closure persists per workspace; explicit Diff actions reopen it and navigation counts only visible tabs.
- **Titlebar:** transparent. The 44px top row reserves the first 80px for the traffic lights; the sidebar toggle follows at x80 in both sidebar modes. Only unused space is draggable, so tab drags and buttons keep their mouse events.
- **Settings dialog:** 800px, a 168px left nav of `ghost` `small` buttons (General, Appearance, Prompts; `ctrl-tab` cycles them), the selected one `selected`. A page is `section()` headers over `card()`s. Settings are rows inside a `secondary` card: label `text_sm` plus a `text_xs` `muted_foreground` description on the left, a 240px control on the right, 1px `border` between rows. Changes apply immediately; there is no Save button.
- **Where a new view goes:**
  - A view of the open workspace is an artifact in a header tab. Reuse the existing tab lifecycle; add a tab kind only for a new artifact.
  - A view not tied to one workspace (settings, repo list) opens with `window.open_dialog`, `w(px(640.))`, like the palette.
  - Artifact-specific panes stay inside their artifact. The file editor fills the central area; Chat remains available through its tabs and shortcuts. The file tree belongs only to Diff, inside the island.
- **Side rows** (`side_row` in `src/app.rs`, left navigation, after Linear's sidebar): 30px tall plus 2px below (a 32px pitch), `mx_2`, a 1px transparent border and 7px padding so icons start 16px from the pane edge, `gap_2`, `rounded(theme.radius)`, `text_sm` in `muted_foreground`. `cursor_row` sets the state: the open item gets `side_on` and `foreground`, other rows `side_hover` on hover. Order: icon (16px), name (`flex_1`, truncated), optional badge, metadata or count (`text_xs`, `muted_foreground`, right-aligned). Group headers (`side_header`): `px_4 pt_4 pb_1`, `text_xs` `MEDIUM` `muted_foreground`; a header's button shows on hover. Sidebar width 244px.
  - Workspace rows are 44px with two lines: the name, then its repos (`text_xs`, `muted_foreground`, `api · web`), so you can see where an agent works without opening it. The open workspace has the pill.
- **Sections:** groups inside the Workspaces list, above the ungrouped workspaces. A header is a side row: section icon (16px, picked from `SECTION_ICONS`, default `Folder`), name in `MEDIUM`, then `ChevronDown`/`ChevronRight` (12px) right after it, and the count (`text_xs`) at the right edge only while folded; all `muted_foreground`. Its workspaces indent 16px. New and renamed sections are named in place: the row turns into an `Input` with the focus ring, `enter` saves, `esc` cancels, clicking away saves. Drag a workspace onto a header to move it in, or onto a workspace to take its slot (in that workspace's section); drag a header onto another to reorder sections. A drop target shows the `primary` border. Deleting a section doesn't confirm (nothing is lost); in the rail a header is just its icon.
- **Zen mode:** `cmd-.`, View › Toggle Zen Mode or the palette shows only the shown tab (chat, Diff, Git or file) on the island `background`: no sidebar, titlebar tabs, workspace header or Features rail. A 44px bar keeps the traffic lights clear, drags the window and holds the tab's own controls (Diff's comparison toolbar). Every shortcut keeps working, so tabs switch within Zen; `cmd-alt-←/→` walks only the shown panes. `cmd-b` (asking for the sidebar), Home or `cmd-.` again ends it. Session-only.
- **Sidebar rail:** `cmd-b` shrinks the sidebar to a 72px rail with 32px icon buttons and tooltips; opening, selecting, and closing files preserve the sidebar’s current state. The toggle moves into the titlebar at the same window position, followed by Commands and New workspace. Expanded, Commands and New workspace sit to the right of the content-sized Home button, with a 4px gap between them. Commands uses the Command icon and the “Commands (cmd-k)” tooltip and accessibility label. Home shows its `cmd-0` hint only while Command alone is held. Both create buttons run the existing `cmd-n` action.
- **Features rail:** fixed at 72px on `sidebar`, beside every workspace artifact and absent on Home. Its only item is Differ, using `rail_button`, a tooltip, and an accessible name. It opens or focuses the single Diff artifact; the pill marks that artifact active. Keep the unviewed/error indicator. The rail has no expansion toggle, resize handle, Commands item, file tree, or artifact-specific context menu; retain the 44px titlebar spacing and align the launcher’s top with Home in both expanded and collapsed sidebar layouts. Pane navigation reaches the launcher; Enter activates it.
- **Diff file tree:** a column on the right inside Diff, on the island `background`, below the artifact-wide comparison toolbar. The toolbar wraps at narrow widths; diff content is clipped to its own column. It is shown by default, hidden with **Files** or `cmd-alt-b` while Diff is active, and resizes from 200–560px with a 244px default; keep the saved width. Visibility is session-only. It is absent from chat/file artifacts and their keyboard focus order. Hiding it while the tree or filter has focus returns focus to Diff. Its `Files` header uses `side_header` styling with a viewed count. Keep 30px rows indented 12px per level, 16px icons and 14px folder chevrons. Use `list_cursor_row` for island hover/selection/focus states. The viewed checkbox also works on folders. Folders come first; single-child folders are joined.
  - Draw decorative 1px vertical guides in `border` at each ancestor's chevron center, from beneath its folder row to the center of its last visible descendant; no horizontal branches. Derive each virtualized row's segments from its depth and the next visible row's depth, including after filtering or folding.
  - Folder labels, chevrons, and compact file prefixes through the final `/` use `foreground` on the island background. Filenames keep their viewed color and open-file weight; status dots, counts, checkboxes, selection backgrounds and focus rings keep their existing treatment. Never dim a whole row.
- **Menus** (right-click menus and dropdowns, not the menu bar): `src/menu.rs`, drawn after Linear's menus (gpui-kit's `PopupMenu` hard-codes 26px rows, 2px separators and full-colour icons). Right-click on sidebar rows opens one at the mouse. A dropdown hangs from the button that opens it (`menu::open_at` with the anchor corner): the git menu under its chevron, the model menu above the composer's model button (also cmd-/; Claude's models, a separator, then Codex's, with a hint naming the backend where the label doesn't), each starting on the current choice. Typing letters jumps to the row that starts with them, as in a Mac menu. The composer's completions use the same `menu::chrome` and `menu::highlight`.
  - `popover` surface, 12px `theme.radius_lg` corners, `p(6px)`, measured from contents and normally 200–440px wide, constrained to an 8px window margin. Keep the 10% `foreground` ring plus soft shadow instead of a border. Labels 14px; hints `text_sm` `muted_foreground`. Completion popups retain their existing `menu::chrome` corners.
  - 32px rows (`menu::ROW_H`), `px(10px) gap(8px)`, highlight an inset 8px `theme.radius` pill in 7% `foreground`; the text color doesn't change. Mouse and arrow keys share one highlight.
  - Action labels take priority over hints; fixed icon, check and chevron slots stay outside the text. Hints yield their space first. Overflowing text uses the tabs' 24px fade into the actual row background, with the full clipped label and hint in a tooltip. Labels only clip when the window forces it; intentional ellipses in action names stay intact.
  - Submenus use the rendered parent's bounds: open right when they fit, otherwise left, otherwise use the roomier side, leaving a traversable 4px gap and an 8px window margin. Hover protection follows the opening direction. If neither side has 200px, click or keyboard activation replaces the parent with the submenu; hover only highlights. A Back row, Left or Escape returns to the parent's selection and scroll position.
  - Panels scroll when their contents exceed the viewport. Keyboard navigation keeps the selected row visible; scrolling a parent closes its adjacent child. Escape dismisses the root menu, restores focus, and an outside click dismisses without activating the content underneath.
  - 16px icons in `faint` (app icons 18px); separators are 1px, full width, 6px space above and below.
  - No header row: say what an item acts on with a right-aligned muted hint instead (the branch on `Copy Branch Name`, the `~/…` path on each path row).
  - At most three groups: open/reveal (`Reveal in Finder`, then `Open in <app>` for each app LaunchServices lists for folders (`src/apps.rs`) with the app's own icon, then `Copy path`; each a submenu with "Workspace folder" plus one row per repo, or a plain item with its target as the hint when there's only one. Git clients list only the repos, Xcode only the repos' projects and hides when there are none; a repo row's menu has the same items for that repo), then git (`Open pull requests`, hidden when there are none), then destructive (`Archive`, `Force archive…`) last, in normal text like Linear's Delete.
  - The current choice or a setting that's on gets `.checked(true)`: a 16px `Check` in `muted_foreground` at the right end (never a `✓` hint).
  - Hide items that don't apply instead of disabling them. No shortcuts in these menus; every item also exists in the palette, which shows them.
  - Sentence case labels; an ellipsis only when the item opens a picker or asks for confirmation.
- **Git menu:** the chevron next to the git button. Groups: the next step (hint "Next"), then sync (Fetch now, Commit and push, Pull, Push, Update from base; agent prompts have a "Queue" hint), then PRs (Create or update, Create draft, Merge PRs… and Open PRs in browser while a PR is open, and with more than one repo a Merge order submenu, the order as its hint, holding each repo's possible moves (Merge web earlier, Merge api later)), then the "Delete remote branches after merge" setting, checked while on. Repo states and errors stay in the git button's tooltip, not as rows that do nothing.
- **Command palette** (`cmd-k`, `src/app/palette.rs`): gpui-kit's `Command` in `menu_dialog`. Each `COMMANDS` row is a `Row(label, icon, action, keywords, handler)`: the handler runs it; the action is only read for its shortcut, shown right-aligned in `muted_foreground` (the newest one-key binding valid where the palette was opened, never a Vim-only key). Keywords are extra words the filter matches. Rows are grouped under headings (`GROUPS` names each group by its first row): Workspace, Chat, Plan, Files and diff, Git, Sections, View, Shark, then Open workspace with one row per workspace, in sidebar order. Rows only one backend can do are left out for the other: `CLAUDE_ONLY` (side question) while the shown chat runs Codex, `CODEX_ONLY` (fast mode) otherwise. Pickers that aren't tied to a button (section, icon, merge order from cmd-k, reopen chat, add repo) go through `open_menu`, with a placeholder that says what they pick, and look the same.
- **Menu bar** (`src/menubar.rs`): items dispatch existing actions, so their shortcuts come from the keymap. Every Shark command in it also exists in the palette; the macOS standard items (Hide, Quit, Minimize, Zoom, Services, Edit) don't need to. Nor do Help's two links (README, Report an Issue); its Keyboard Shortcuts item opens the palette, which shows each command's shortcut. Edit uses gpui-kit's input actions with an `os_action`, so it works in any text field.
- **Header:** the 44px titlebar sits above the island, with 4px gaps between tabs. Inside the island, a 44px header with 16px horizontal padding and `border_b_1` holds the branch on the left and the git button (`src/sync/`) on the right.
- **Branch button:** `ghost` `xsmall`, `text_xs` `muted_foreground`: a 12px `GitBranch` (`Layers` while the branch is part of a stack), `base ← branch` (the base without `origin/`: the stacked repos' parent when they share one, else the base every repo shares, else the branch alone), then the stack position `2/3`. The label truncates; the position doesn't. Either click opens the branch menu.
- **Branch menu:** three groups. The stack's branches, newest on top (the GitHub/Graphite order), the current one checked, hint `#12 · open` or `workspace`, prefixed with the repo in a multi-repo workspace; with several stacked repos, one `Stack · <repo>` submenu each (hint `2 of 3`). Then the actions: the restack row named after its target (`Rebase onto logic`, hint the behind count; `Parent merged · rebase onto main`), New workspace on top…, Insert workspace below… (hint `between logic and ui`), Copy branch name, Change base…. Then Open branch on GitHub and Open pull request. The sidebar's right-click menu has the same rows; "Branch menu…" in cmd-k opens it under the button, like "Git menu…".
- **Git button:** a `small` button plus a `ghost` `xsmall` chevron for the git menu. It is the header's one primary button: `primary` for a step to run, `outline` with a `warning_foreground` icon when something needs the agent or a human, `ghost` for a wait. Disabled while the agent runs if the step writes.
- **Tabs:** equal-width 200px × 28px rounded rectangles (capped to the strip width in narrow windows) (`theme.radius`, `px_2p5`, 14px icon + `text_sm` label) in the titlebar. Active: `secondary` + `foreground`. Inactive: `background` + `muted_foreground`; hover: `secondary_hover` + `foreground`.
- **Workspace tabs:** chats, optional Diff, and files share a persisted mixed strip. Tabs are up to 200px each and shrink to 100px before scrolling; edge arrows reveal hidden tabs and mark unread chats. Drag any tab into another tab’s slot in the same workspace without changing focus or buffers. New and explicitly reopened tabs append; file replacement keeps its slot. Inactive labels use `sidebar_foreground`, like the navigation pane; selected and hovered tabs use `foreground`. Diff starts closed in new workspaces; Differ in Features opens it or focuses its existing tab. Saved open/closed choices are preserved. `ctrl-tab` / `ctrl-shift-tab` visit every tab in that order. Long labels fade over their last 24px only when they overflow, with the full title or file path in a tooltip. Every chat shows its title (first line of the first message), or "New chat" while untitled, even when it is the only chat. Each gets a `ghost` `xsmall` × button overlaid on hover, leaving the full label width available when hidden. The icon is a `primary` spinner while that chat runs, and `MessageSquare` with a 6px `primary` dot when a turn ended unseen. A `ghost` `xsmall` + stays outside the shrinking strip. File tabs have a close button and an unsaved dot; Command-clicking a tree file adds a tab or selects its existing tab. Ordinary opening replaces the selected file after confirming unsaved edits. Closing a background file preserves the current view. Workspace switching, archiving and quitting check unsaved edits in every open file. File identities survive workspace switches and restart, restoring validated text files from disk in the background without changing selection or focus. Failed restores are reported together and kept for retry. Only confirmed explicit closes remove identities. Shark owns titlebar gestures (`app_owns_titlebar_drag`); only a press beginning in designated empty chrome may call `start_window_move`, and double-click uses the system titlebar action. Controls are outside these regions. Use plain tooltips here, not `tooltip_with_action`: the header redraws on every tree key and the keymap lookup costs ~40 ms a frame.
- **Question card** (`src/chat/question.rs`): the agent's questions (claude's AskUserQuestion, Codex's request_user_input), above the composer in the side-question card's frame (composer width, `muted`, `border`/`primary` while focused, `radius_lg`). Header `text_xs` `muted_foreground`: `MessageCircleQuestionMark` + "The agent asks · <header>", "Question n of m" with several, × (answer in the chat). The body is gpui-component's `Questionnaire` at `Size::Small`, one question at a time: title, numbered choice cards (radio, or checkbox for multiple choice) with their descriptions, a "Something else…" `Input`, the validation line, and Previous / Skip / Next / Submit. The card uses at most half the window height; its question content scrolls while the header and action buttons stay visible. Keyboard focus reveals choices and the free-text input, including after resizing; manual scrolling stays where the user puts it. `faint` key hints show while it has focus. It takes the focus on arrival only from this chat's transcript, queue or an empty composer. Answered, it leaves a standalone **Question** row (same icon) whose summary is the answers. While it waits, the chat's tab icon is the same icon in `warning_foreground`.
- **Side-question card:** above the composer at the composer's width, `muted` fill, `border` (`primary` while focused), `radius_lg`. Header `text_xs` `muted_foreground`: `MessageCircleQuestionMark` + "Side question · not added to chat", spinner while answering, × to dismiss. Then the question (`text_sm` `MEDIUM`), the answer as markdown (max 280px, scrolls), and key hints.
- **Home** (`src/app/home.rs`, `cmd-0`): replaces the main area (header + one scrolling `max_w(px(760.))` column, `gap_8`) while `home.on` or no workspace is open; opening a workspace leaves it. The sidebar's content-sized top button (`House`, "Home", with `cmd-0` while Command alone is held) opens it. Top to bottom, so a returning user's workspaces sit above the fold: the prompt (`text_base` title, an `Input` in a `secondary` card with the focus ring, then key hints; `tab` switches new workspace ↔ Ask Shark), the What's new line after an update (also after one from before the line existed: empty `last_seen_version` with workspaces), the Ask Shark card (styled like the side-question card; a claude error shows once, in place of the answer), missing tools (`deps::render_setup`, `w_full` so its fix commands truncate in a narrow window), the workspace list (headers `text_xs` `MEDIUM` + count; rows `list_cursor_row` on `list_hover`, status icon as in the sidebar, name, `GitMerge` "Merged", last activity, the Needs you label in `warning_foreground`, branch · repos · chats, then each repo's summary without "GitHub unavailable", or `faint` "checking…"; the cursor's row is scrolled into view), the Get started `card` (one 36px row per item: `CircleCheck` `success_foreground` or `Circle`, a `ghost` `xsmall` button and its `Kbd` while undone; with workspaces, a one-line "Get started · n of 5" button that expands it) and the cmd-k hint until the palette was opened once, then the appearance `card` (mode pills, theme family `Select`, "All settings" + `cmd-,`). What waits on the user and last activity are read off the UI thread when Home opens and when a turn ends, re-reading only transcripts whose length or mtime changed. - **Plan pane** (`src/plan.rs`): a column right of the transcript, inside the chat, 48% wide (min 340px), 1px `border` on its left. It opens with plan mode and when a plan arrives.
  - Header 40px: `ClipboardList` + "Plan" (`MEDIUM`), version pills (22px `rounded_full`, `text_xs`; current on `secondary`; the approved one has a 12px `Check` in `success_foreground`), then `+n` `success_foreground` / `−n` `danger_foreground` word counts, a `ghost` `xsmall` "Changes" toggle (`selected` while on) and ×. The header's bottom border is `primary` while the pane has focus.
  - Body: the version as markdown, 14px, scrolling. Changes from the previous version are inline: added text on `success` at 18% over `background`, removed text struck through on `danger` at 14% (removed reads quieter than added). - **Rows inside the island:** 28px for compact rows (tool calls, lists in dialogs). Transcript blocks are `px_4 py_1p5`.
- **Agent activity in the transcript:** prose is what people read; tool calls are evidence.
  - A run of tool calls between two pieces of prose is **one row**: chevron, a summary counted by verb ("Read 4 files, ran 2 commands"), `muted_foreground`. Add a verb to `group_summary` in `src/chat.rs` rather than listing tool names.
  - While a call runs, the row also shows `· <Tool> <summary>` for the call in flight, and a `Spinner`.
  - Failures show on the collapsed row as `X` + "N failed" in `danger_foreground`, so they're never hidden by collapsing.
  - Expanded, each call is its own 28px row, indented 22px to line up with the summary text, and each opens to its output.
  - Skills (`Skill`) and subagents (`Agent`/`Task`) are never grouped: they get their own row with a `BookOpen` / `Bot` icon, because they say *what* the agent is doing. Add a tool to `standalone()` only if it carries that kind of intent.
  - Tool paths are shown relative to the workspace (`api/src/a.rs`).
  - A turn ends with an info line: "done · 48s · $0.12", or "interrupted · 12s · $0.03" after `ctrl-c`. A turn cut off by quitting gets "interrupted" on replay.
- **Composer completions** (`@` files, `/` skills; `src/complete.rs`):
  - The menu opens upward from the composer, at its width, over the transcript, on the menu surface (`menu::chrome`). It shows 8 rows of 32px (`menu::ROW_H`) and scrolls to more, with a `faint` key-hint footer.
  - Each row has an icon: a file's or folder's colored icon (see Icons), else a 14px `File` / `Folder` / `SquareSlash`; the name in `foreground`, the folder or description in `text_xs` `muted_foreground` (truncated), and on the right the repo (`FolderGit2` + name) when the workspace has more than one repo, or a command's argument hint in `faint`.

  - A pick becomes an inline chip, an atomic `InlineToken` whose text is `@repo/path` and whose label is `name · repo`. Paths are workspace-relative, so the repo is part of what gets sent. Typing `repo/` scopes the search to one repo.
  - Sources never block typing. Files come from `git ls-files` per repo and skills from claude's `initialize` control request. Both load when the chat opens and refresh in the background each time the menu opens; until a refresh lands, the old list (for skills, the on-disk cache) is used.
- **Message queue** (`render_queue` in `src/chat.rs`): messages sent while the agent runs sit inside the composer card, above the input, separated by a 1px `border`. The panel only renders while something is queued.
  - A 24px `text_xs` `muted_foreground` header: "2 queued · sends when the turn ends" (or "· paused while you edit"), with `faint` key hints on the right: `↑ manage` while the composer has focus, and the queue keys while the queue has focus.
  - 28px rows in send order, top row first: a `CornerDownRight` icon, the message's first line (`foreground`, truncated), then row actions `ArrowUp` send now, `Pencil` edit, `Trash` delete (`ghost` `xsmall`). The focused row is `list_active` plus a 2px `primary` left bar. 5 rows show, then it scrolls.
  - The preview is cut once when the message is queued (first line, 200 characters), so a long paste isn't shaped on every frame.
  - The composer footer names what Enter does: "send", "queue" while the agent runs (plus `cmd-enter` "send now"), "save" while editing a queued message.
- **Radii:** `theme.radius` (8px) for rows, inputs and code blocks; `theme.radius_lg` (12px) for the island, cards and dialogs; `rounded_full()` for pills and dots.
- **Borders, not shadows:** `shadow` is off. Separate with a 1px `border` or a surface change. Prefer fewer separators.
- **Spacing:** the gpui scale only (`gap_1`=4px, `gap_1p5`=6px, `gap_2`=8px, `px_3`=12px, `px_4`=16px), plus the fixed sizes above.
- **Empty state:** centered, `gap_3`. A 32px Lucide icon in `faint`, a `text_base` `foreground` title, then rows of `Kbd` chips with a `text_sm` `muted_foreground` label.

## Icons and status
- **Lucide** via `gpui_kit::assets::IconName`; the full catalog is embedded (`AllAssets`). File `circle-dashed.svg` maps to `IconName::CircleDashed`; browse them in `~/.cargo/registry/src/*/gpui-kit-assets-0.8.0/assets/icons/`.

- **No text glyphs as icons** (`●`, `▸`, `✓`).

Add a type or folder name to `file_icon.rs` (and its SVG to `assets/file-icons/`); add a `<name>_light.svg` when a glyph fades on a light background.

## Interaction states
- **Focus:**
  - Focused list row: in the side panes the `side_on` pill plus a 1px `primary` border, shown only while the pane has focus (no indigo fill); inside the island `list_active` plus a 1px `primary` border, or a 2px `primary` left bar (transcript). The tint alone is not visible enough.
  - Inputs and buttons use gpui-kit's `ring`.
- **Hover:** a background step (`list_hover` / `side_hover` / `secondary_hover`) or, for tabs, text color. Never the only way to discover something.
- **Disabled:** `muted_foreground` text and the component's `.disabled(true)`; no hover; not focusable.
- **Motion:** use `Spinner` and gpui-kit's built-ins. During reordering, constrain tabs to horizontal movement inside their strip and sidebar rows to vertical movement inside their pane; animate neighboring items live with gpui-kit's motion support and respect reduced motion. No entrance effects (the palette uses `DialogEntrance::None`).
- **Selection:** text selection is translucent indigo (`selection.background`); keep it translucent so selected text stays readable.

## Copy buttons
- **Never move anything.** A hover-revealed button is `invisible()` until its group is hovered, so its slot is always laid out. Showing it, and the check after a copy, changes no size.
- **Never cover text.** Content reserves the corner the button sits in: the user card's text column stops before it, tool output has `pr_8`, code blocks keep the 28px top padding the language label had.
- **Where:** user messages top-right of the card; a reply on its closing line ("done · 48s", always shown on the latest reply); code blocks and tool output in their top-right corner; the plan pane and side-question card in the header before ×, always shown.
- Hover is never the only way: `y` copies the selected transcript row or the shown plan, `c` the side answer, and the palette has "Copy selected message" and "Copy plan".

## Copy and destructive actions
- **Confirm only when data is lost.** Archive doesn't confirm; force-archive does.
- **Confirm dialogs:**
  - Title `Verb {name}?`.
  - The description states the consequence.
  - `ok_text` is the verb; use `show_cancel(true)`.
- **Errors name the fix**, including the key or the palette command: "Add a repo first (Add repo in cmd-k)".
- **Progress notifications** end with an ellipsis: "Creating PRs…".

## Keyboard and focus
- **Focus handling:** every view that handles keys gets a `key_context(..)` and a `FocusHandle`.
- **Bindings** go in `bind_keys` in `src/main.rs`. There are no `space` leader chords: a command without a key is found in `cmd-k`.
  - **Vim mode** (Settings › General, `ctrl-cmd-v`, `State::vim`) is one switch for the editor, the composer and the lists. While it's on the root view carries the `Vim` key context; Vim-style keys (`j/k`, `gg`, `G`, `ctrl-d/u`, `h/l`, `g t`, `]c`/`[c`, the queue's `shift-j/k`) are bound with the `vim(..)` helper under `Vim > (…)`, and `ctrl-w h/l` under `Vim`. Each has a non-Vim key that always works: the arrows, `home`/`end` and `pageup`/`pagedown` in lists (`ARROWS`), `←/→` to fold and switch plan versions, `alt-↑/↓` for changes and queue order, `cmd-alt-←/→` for panes. `Shark::set_vim` applies a change everywhere at once.
  - For lists, add the context to `LIST`, `MOVE` and `ARROWS`, and handle `SelectNext/Prev/First/Last/Confirm`, plus `PageDown/PageUp` where the list scrolls. The sidebar currently doesn't handle `PageDown/PageUp`.
- **New global commands** need:
  - an `actions!` entry;
  - a `COMMANDS` row with its action and keywords;
  - a menu-bar item where it fits;
  - a direct shortcut only when it's used often; otherwise the palette is the way in;
  - a line in the keys table in docs/manual.md.
- **Row actions** act on the cursor row of the focused list, otherwise on the open item (see `archive`). They get a single-key binding in the list's context plus a palette row.

## Gotchas
- **Unknown theme keys are silently ignored.** Copy key names from `ThemeConfigColors` in gpui-component's `theme/schema.rs` (the link color is `link`, not `link.foreground`). The `themes_parse` test checks the core keys; extend it when you rely on a new one.
- **`list.active.background` alpha is capped at 20%** by gpui-kit. Setting a higher alpha does nothing.
- **The `tab.*` theme keys are unused;** tabs use `background` / `secondary` / `secondary_hover` and `foreground` / `muted_foreground`.
- **`cx.theme()` borrows `cx`.** Copy the colors you need into locals before calling `cx.listener(..)` or other `&mut cx` methods (see the composer in `src/chat.rs`). Don't clone the whole `Theme` per render.

## Checklist for a UI change
1. Colors come from theme tokens (or `faint`), with no hex in views. Every new text pair meets the contrast rules.
2. Sizes, radii, type and icons come from the tables above. Status uses the status vocabulary.
3. The command is reachable by keyboard and listed in the palette and the keys table in docs/manual.md.
4. Dialogs apply `inter_features()`.
5. `cargo test --features test-support` passes (the headless keyboard test covers focus and key contexts).
6. Checked by eye in both modes, without changing the system appearance:
   ```sh
   ./target/debug/shark &                                         # follows the system (dark here)
   ./target/debug/shark -NSRequiresAquaSystemAppearance YES &     # forces light for this process
   screencapture -x -o -l <window-id> .context/shot.png           # window id: CGWindowListCopyWindowInfo, owner PID
   ```

### Workspace quick open

- `cmd-shift-o`, File → Open workspace…, and the command palette open the dedicated picker in `src/app/workspace_picker.rs`. While the `cmd-o` app switcher is open, this shortcut still reverses its selection. Releasing Command never confirms the workspace picker.
- Reuse `CommandState`, custom variable-height `CommandItem` rows, and the 640px `menu_dialog` surface, constrained to the viewport. Focus search immediately; arrows navigate, Enter/click opens, one Escape dismisses and restores focus. Footer: `↑↓ Navigate · ↵ Open · Esc Close`.
- Include every live workspace, including folded sections. Score workspace and each repository name separately with the completion matcher, treating spaces, hyphens, underscores, slashes and dots as word separators, taking the best score, then recorded interaction recency, then sidebar order. With no query, select the most recent other workspace (most recent from Home). Query changes select the best match; background status updates preserve order and selected identity.
- Each row shows the workspace name, Current when applicable, last user interaction with its exact time in a tooltip, and one compact line per repo. Show explicit Draft/Open/Merged/Closed/No PR/Not checked/Status unavailable labels from `overview_repos`; failing checks never hide Draft. Full names and statuses have accessible labels and overflow tooltips. Empty states distinguish no workspaces from no matches.
- A fixed 16px status icon precedes the name, shared with the sidebar: the primary `LoaderCircle` spinner while an agent runs, otherwise warning `CircleAlert` for needs-you, success `CircleCheck` for unread, or muted `CircleDashed` for idle. Details align below the name with an 8px gap after the icon. A compact `text_xs` line shows the running-chat count, needs-you action, or Unread; retain a needs-you action alongside the count when another chat runs. Idle has no extra line. Only running agents animate; Git checks keep static icons. Status updates preserve the query, result order, and selected workspace.
- `Workspace.last_interacted_at` stores optional Unix milliseconds. Successful explicit navigation and keyboard/click/scroll activity in visible workspace content count; Home, picker browsing, startup restore, activation, agent output and polling do not. Successful workspace dialog actions count. Coalesce recency saves once per second and flush through the close/quit storage guard. Unknown timestamps sort last and display No recorded interaction.
- Confirm destinations by name and resolve them again after unsaved-edit confirmation, before changing any buffers. Removed or archiving destinations preserve the current edits. Opening the current workspace preserves its view; canceled confirmation never records destination recency.
