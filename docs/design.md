# Shark design rules

Read this before adding or changing UI. Shark's look is modeled on Linear: a calm, dense, keyboard-first tool where people read for long stretches. If a rule here is wrong for your feature, change the rule here in the same change; don't silently diverge.

## Principles
1. **Reading comes first.** Most time is spent reading transcripts. Contrast, line length and font legibility beat decoration.
2. **Keyboard first.** Every command is reachable from the keyboard and listed in the command palette. The mouse is optional.
3. **Quiet chrome, one accent.** Neutral grays everywhere. Indigo (`primary`) means only three things: keyboard focus, "the agent is running", and the primary button. Status uses icon + text color, never colored fills.
4. **Dark and light are equal.** Every change is checked in both. Never hard-code a color that works in only one mode.
5. **Reuse before building.** Use the gpui-kit component or a pattern already in `src/app.rs` / `src/chat.rs` before writing a new one.

## Theme
- **Source of truth:** `assets/themes/*.json`, one `ThemeSet` per family with `<Family> Dark` and `<Family> Light`, listed in `THEMES` in `src/settings.rs`. Change colors there, not in Rust. `linear.json` (the default) is hand-tuned; the others are generated by `python3 docs/themes.py` from codigrate palettes, which lifts text colors to the contrast floors below. Edit the palette in the script and regenerate; don't hand-edit generated files.
- **Applying:** `settings::apply` installs the saved light and dark themes with font overrides baked in (a mode switch reloads the config), and `Shark` re-applies it on system appearance changes while the mode is System.
- **The table below lists Linear's values.** Every theme must define the same tokens and meet the same contrast rules.
- **In code:** read colors from `cx.theme()` (`ActiveTheme`). No hex values in views; the only exception is `faint()` in `src/app.rs`, because gpui-kit has no token for it.

### Contrast rules
Measure APCA (Lc) against **every surface the text can sit on**, including hover and selected rows (`background`, `sidebar`, `secondary`, `muted`, `list_active`, `list_hover`, `sidebar_accent`):

| Text | Minimum | Current lowest |
|---|---|---|
| Prose and titles on `background` / cards | Lc 90 | 92.2 dark, 96.2 light |
| Any other readable text: labels, metadata, `muted_foreground`, text in selected/hover rows | Lc 70 | 71.6 dark, 72.6 light |
| Status text and links | Lc 60 | 61.3 dark, 61.2 light |
| Hints (`faint`), never essential | Lc 30 | 33.0 dark, 38.5 light |

Run `python3 docs/contrast.py '<fg>' '<bg>' …` for every new pair. Also: no pure white on near-black, and no font weight below 400.

## Typography
- **UI font:** Inter by default (Settings can swap the UI and code font for any installed font), embedded from `assets/fonts/` (400, 500, 600, 700, italic 400). Use only those weights.
- **Mono font:** JetBrains Mono NL (no ligatures), 400 and 700. **Not inherited:** set `.font_family(theme.mono_font_family.clone()).text_size(theme.mono_font_size)` on code and tool output.
- **Character variants:** `inter_features()` in `src/app.rs` turns on serifed I, tailed l and slashed 0 so paths and hashes are unambiguous. It is applied on the root view and must also be applied to every dialog (`d.font_features(inter_features())`), because dialogs, the palette and notifications render outside the root view.
- **Sizes:** `font.size` is 15 and the window rem equals it:

| Helper | Size | Use for |
|---|---|---|
| `text_xs()` | 11.25px | Metadata, section headers, info rows, status labels |
| `text_sm()` | 13.1px | Default UI: sidebar rows, tabs, buttons, tool rows |
| `text_size(px(14.))` + `line_height(relative(1.5))` | 14px | Transcript prose and user messages |
| `text_base()` | 15px | Empty-state and dialog titles |

- **Weights:** 400 for text; `FontWeight::MEDIUM` for emphasis (active sidebar item, tool names, section headers); `SEMIBOLD` for markdown headings only.
- Sentence case for labels and headers ("Workspaces", not "WORKSPACES").
- **Line length:** prose sits in a centered `max_w(px(680.))` column (~70 characters). The composer card is `max_w(px(712.))`.

## Layout
- **Inverted L:** the sidebar and the window's top edge share `sidebar`. Content sits in one island: inset 8px top, right and bottom, `rounded(theme.radius_lg)`, 1px `border`, `bg(background)`, `overflow_hidden()`.
- **Titlebar:** transparent. The sidebar starts with a 36px drag area for the traffic lights; put no controls there.
- **Settings dialog:** pill tabs (Appearance, Prompts) styled like header tabs but active on `accent`, so they show on cards too. Settings are rows inside a `secondary` card: label `text_sm` plus a `text_xs` `muted_foreground` description on the left, a 240px control on the right, 1px `border` between rows. Changes apply immediately; there is no Save button.
- **Where a new view goes:**
  - A view of the open workspace becomes a header tab (add a `Tab` variant).
  - A view not tied to one workspace (settings, repo list) opens with `window.open_dialog`, `w(px(640.))`, like the palette.
  - Don't add a second sidebar or panes outside the island. Panes inside it (the file tree, the editor next to the chat) are columns separated by a 1px `border`.
- **Sidebar row:** 28px tall, `mx_2 mb_1 px_2 gap_2` (the 4px gap keeps hover and selection backgrounds apart), `rounded(theme.radius)`, `text_sm`. Order: status icon (14px), name (`flex_1`, truncated), optional badge, metadata (`text_xs`, `muted_foreground`). Sidebar width 244px.
  - Workspace rows are 44px with two lines: the name, then its repos (`text_xs`, `muted_foreground`, `api · web`), so you can see where an agent works without opening it.
- **Sections:** groups inside the Workspaces list, above the ungrouped workspaces. A header is a 28px row: section icon (14px, picked from `SECTION_ICONS`, default `Folder`), name in `MEDIUM`, the count (`text_xs`) only while folded, then `ChevronDown`/`ChevronRight` (12px); all `muted_foreground`. Its workspaces indent 16px. New and renamed sections are named in place: the row turns into an `Input` with the focus ring, `enter` saves, `esc` cancels, clicking away saves. Drag a workspace onto a header to move it in, or onto a workspace to take its slot (in that workspace's section); drag a header onto another to reorder sections. A drop target shows the `primary` border. Deleting a section doesn't confirm (nothing is lost); in the rail a header is just its icon.
- **Sidebar rail:** `cmd-b` shrinks the sidebar to 48px icons with tooltips; opening a file does it automatically and closing the file undoes it unless the user toggled it. The header then pads left to clear the traffic lights.
- **File tree:** 260px column on the right of the Diff and file views, `Files` header with "n/m viewed", 28px rows indented 12px per level, then the `v` checkbox (a folder's box is ticked when all its files are viewed and toggles them all). Folders first; single-child folders are joined.
- **Context menus** (right-click, not the menu bar): right-click on sidebar rows opens `src/menu.rs`, drawn after Linear's menus (gpui-kit's `PopupMenu` hard-codes 26px rows, 2px separators and full-colour icons):
  - `popover` surface, `radius` 8px, `p(4px)`, 200–340px wide, a 10% `foreground` ring plus a soft shadow instead of a border. 13px text.
  - 28px rows, `px(8px) gap(8px)`, highlight an inset 4px-radius pill in 7% `foreground`; the text color doesn't change. Mouse and arrow keys share one highlight.
  - 14px icons in `muted_foreground`; separators are 1px, full width, 4px space above and below.
  - No header row: say what an item acts on with a right-aligned muted hint instead (the branch on `Copy Branch Name`, the `~/…` path on each path row).
  - At most three groups: open/reveal (`Reveal in Finder`, `Open in Terminal`, `Copy Path`, one submenu each with "Workspace folder" plus one row per repo), then git (`Open Pull Requests`, hidden when there are none), then destructive (`Archive`, `Force Archive…`) last, in normal text like Linear's Delete.
  - Hide items that don't apply instead of disabling them. No shortcuts in these menus; every item also exists in the palette.
  - Title Case labels; an ellipsis only when the item asks for confirmation.
- **Menu bar** (`src/menubar.rs`): items dispatch existing actions, so their shortcuts come from the keymap. Every Shark command in it also exists in the palette; the macOS standard items (Hide, Quit, Minimize, Zoom, Services, Edit) don't need to. Edit uses gpui-kit's input actions with an `os_action`, so it works in any text field.
- **Header:** 44px, `px_3`, `border_b_1` in `border`. Tabs on the left; on the right: branch (12px `GitBranch` + `text_xs`), the git button (`src/sync/`), optional badges, then status (6px `rounded_full` dot + "Running"/"Idle").
- **Git button:** a `small` button plus a `ghost` `xsmall` chevron for the git menu. It is the header's one primary button: `primary` for a step to run, `outline` with a `warning_foreground` icon when something needs the agent or a human, `ghost` for a wait. Disabled while the agent runs if the step writes.
- **Tabs:** 26px pills (`rounded_full`, `px_2p5`, 14px icon + `text_sm` label). Active: `secondary` + `foreground`. Inactive: `muted_foreground`, hover → `foreground`.
- **Chat tabs:** one pill per chat, before Diff. A single chat reads "Chat"; with more, each shows its title (first line of the first message, max 180px, truncated), and the current one gets a `ghost` `xsmall` × button. The icon is a `primary` spinner while that chat runs, and `MessageSquare` with a 6px `primary` dot when a turn ended unseen. A `ghost` `xsmall` + follows the last tab. Use plain `tooltip("… (key)")` here, not `tooltip_with_action`: the header redraws on every tree key and the keymap lookup costs ~40 ms a frame.
- **Side-question card:** above the composer at the composer's width, `muted` fill, `border` (`primary` while focused), `radius_lg`. Header `text_xs` `muted_foreground`: `MessageCircleQuestionMark` + "Side question · not added to chat", spinner while answering, × to dismiss. Then the question (`text_sm` `MEDIUM`), the answer as markdown (max 280px, scrolls), and key hints.
- **Plan pane** (`src/plan.rs`): a column right of the transcript, inside the chat, 48% wide (min 340px), 1px `border` on its left. It opens with plan mode and when a plan arrives.
  - Header 40px: `ClipboardList` + "Plan" (`MEDIUM`), version pills (22px `rounded_full`, `text_xs`; current on `secondary`; the approved one has a 12px `Check` in `success_foreground`), then `+n` `success_foreground` / `−n` `danger_foreground` word counts, a `ghost` `xsmall` "Changes" toggle (`selected` while on) and ×. The header's bottom border is `primary` while the pane has focus.
  - Body: the version as markdown, 14px, scrolling. Changes from the previous version are inline: added text on `success` at 18% over `background`, removed text struck through on `danger` at 14% (removed reads quieter than added). These two are `<mark color>` hex values computed from the theme, the one place a view passes a color as text; the pane rebuilds them on a theme switch. A changed code block shows as a `diff` block.
  - Footer 44px: key hints in `text_xs`, then a `ghost` "Build in new chat" (`Plus`) and the view's one primary button, "Approve and build" (`Hammer`), on the newest version until it's approved, then `Check` + "Approved".
  - Empty state: `ClipboardList`, "No plan yet", what will appear, and `shift-tab` "plan mode on/off".
  - In the transcript a submitted plan is a standalone row: `ClipboardList`, **Plan**, `v2 · <title>`, `Check`; enter opens that version.
  - The composer's **Plan** button is `ghost` `xsmall` and `selected` while plan mode is on.
- **Rows inside the island:** 28px for compact rows (tool calls, lists in dialogs). Transcript blocks are `px_4 py_1p5`.
- **Agent activity in the transcript:** prose is what people read; tool calls are evidence.
  - A run of tool calls between two pieces of prose is **one row**: chevron, a summary counted by verb ("Read 4 files, ran 2 commands"), `muted_foreground`. Add a verb to `group_summary` in `src/chat.rs` rather than listing tool names.
  - While a call runs, the row also shows `· <Tool> <summary>` for the call in flight, and a `Spinner`.
  - Failures show on the collapsed row as `X` + "N failed" in `danger_foreground`, so they're never hidden by collapsing.
  - Expanded, each call is its own 28px row, indented 22px to line up with the summary text, and each opens to its output.
  - Skills (`Skill`) and subagents (`Agent`/`Task`) are never grouped: they get their own row with a `BookOpen` / `Bot` icon, because they say *what* the agent is doing. Add a tool to `standalone()` only if it carries that kind of intent.
  - Tool paths are shown relative to the workspace (`api/src/a.rs`).
  - A turn ends with an info line: "done · 48s · $0.12", or "interrupted · 12s · $0.03" after `ctrl-c`. A turn cut off by quitting gets "interrupted" on replay.
- **Composer completions** (`@` files, `/` skills; `src/complete.rs`):
  - The menu opens upward from the composer, at its width, over the transcript: `secondary` card, 1px `border`, `radius_lg`, `p_1`. It shows 8 rows of 28px and scrolls to more, with a `faint` key-hint footer.
  - Each row has a 14px `File` / `Folder` / `SquareSlash` icon, the name in `foreground`, the folder or description in `text_xs` `muted_foreground` (truncated), and on the right the repo (`FolderGit2` + name) when the workspace has more than one repo, or a command's argument hint in `faint`.
  - The selected row is `list_active`, others hover `list_hover`. The first row starts selected. ↑/↓ move, Enter/Tab add, Esc closes and stays in the composer. With no match, Enter sends.
  - A pick becomes an inline chip, an atomic `InlineToken` whose text is `@repo/path` and whose label is `name · repo`. Paths are workspace-relative, so the repo is part of what gets sent. Typing `repo/` scopes the search to one repo.
  - Sources never block typing. Files come from `git ls-files` per repo and skills from claude's `initialize` control request. Both load when the chat opens and refresh in the background each time the menu opens; until a refresh lands, the old list (for skills, the on-disk cache) is used.
- **Message queue** (`render_queue` in `src/chat.rs`): messages sent while the agent runs sit inside the composer card, above the input, separated by a 1px `border`. The panel only renders while something is queued.
  - A 24px `text_xs` `muted_foreground` header: "2 queued · sends when the turn ends" (or "· paused while you edit"), with `faint` key hints on the right: `↑ manage` while the composer has focus, and the queue keys while the queue has focus.
  - 28px rows in send order, top row first: a `CornerDownRight` icon, the message's first line (`foreground`, truncated), then row actions `ArrowUp` send now, `Pencil` edit, `Trash` delete (`ghost` `xsmall`). The focused row is `list_active` plus a 2px `primary` left bar. 5 rows show, then it scrolls.
  - The preview is cut once when the message is queued (first line, 200 characters), so a long paste isn't shaped on every frame.
  - The composer footer names what Enter does: "send", "queue" while the agent runs (plus `cmd-enter` "send now"), "save" while editing a queued message.
- **Radii:** `theme.radius` (8px) for rows, inputs and code blocks; `theme.radius_lg` (12px) for the island, cards and dialogs; `rounded_full()` for pills and dots.
- **Borders, not shadows:** `shadow` is off. Separate with a 1px `border` or a surface change. Prefer fewer separators.
- **Spacing:** the gpui scale only (`gap_1`=4px, `gap_1p5`=6px, `gap_2`=8px, `px_3`=12px, `px_4`=16px), plus the fixed sizes above.
- **Empty state:** centered, `gap_3`. A 32px Lucide icon in `faint`, a `text_base` `foreground` title, then rows of `Kbd` chips with a `text_sm` `muted_foreground` label.

## Icons and status
- **Lucide** via `gpui_kit::assets::IconName`; the full catalog is embedded (`AllAssets`). File `circle-dashed.svg` maps to `IconName::CircleDashed`; browse them in `~/.cargo/registry/src/*/gpui-kit-assets-0.8.0/assets/icons/`.
- **Sizes:** `Icon::new(..).with_size(px(14.))` in rows and tabs; 12px next to `text_xs`; 32px only in empty states.
- **Color:** icons inherit the text color. Decorative icons are `muted_foreground` or `faint`; status icons use the status `*_foreground` tokens.
- **No text glyphs as icons** (`●`, `▸`, `✓`).
- **Status vocabulary.** Extend this table when you add a state, rather than inventing one ad hoc:

| State | Element |
|---|---|
| Agent idle | `CircleDashed`, `muted_foreground` |
| Agent running | `Spinner` (sidebar: `.icon(IconName::LoaderCircle).color(theme.primary)`); header dot in `primary` |
| Workspace finished off screen (unread) | Sidebar `CircleCheck` in `success_foreground` until opened |
| Workspace needs you (its git step is yours) | Sidebar `CircleAlert` in `warning_foreground`; the second line shows the step instead of the repos. The spinner outranks it, it outranks unread |
| Tool pending / done / failed | `Spinner` / `Check` muted / `X` in `danger_foreground` |
| Tool group with failures | `X` + "N failed" in `danger_foreground`, on the collapsed row |
| Message queued for a busy agent | `Clock` 12px + "Queued · …" in `text_xs` `muted_foreground` inside the user card, until claude reads it |
| Skill / subagent row | `BookOpen` / `Bot`, `muted_foreground`, before the tool name |
| Collapsed / expanded | `ChevronRight` / `ChevronDown` |
| Changed file added / deleted / other | `FilePlus` / `FileMinus` / `FileDiff`, `muted_foreground`; `+n` `success_foreground`, `−n` `danger_foreground` |
| File viewed / changed since viewed | Checked `Checkbox` and the name in `muted_foreground` / 6px `warning_foreground` dot |
| Diff loading / git failed / no changes | Empty state with a `faint` 32px `Spinner` / `TriangleAlert` in `warning_foreground` and git's error / `FileDiff` in `faint`; the tab reads `Diff` / `Diff · error` / `Diff · 0` |
| Unsaved edits / changed on disk | 6px `foreground` dot after the file name / `TriangleAlert` in `warning_foreground` with Reload and Keep mine |
| Pending diff comment | Annotation under its line: 14px `MessageSquare` in `muted_foreground`, the text in `foreground`; the diff cursor is the selected line |
| Vim mode | Mono `text_xs` pill on `secondary`: `NORMAL`, `INSERT`, `VISUAL`, `V-LINE` plus pending keys; `VIM OFF` without the fill |
| Git step to run | Its own icon (`GitCommitHorizontal`, `ArrowUp`/`ArrowDown`, `GitPullRequestCreate`, `GitMerge`, …) in a `primary` button |
| Git needs attention (conflicts, failing checks, detached HEAD, git error) | `TriangleAlert` in `warning_foreground`, `outline` button |
| Git waiting (GitHub catching up, checks running, review) / reading / step running | `GitPullRequest` / static `RefreshCw`, `ghost` button |

  Only the agent-running state uses a spinner or `primary`. Other pending states (checks running, syncing) use a static icon.
- **Badges** are a status icon (14px in rows, 12px in the header), optionally followed by a `text_xs` label. Don't use `Tag` or `Badge` fills in chrome.

## Interaction states
- **Focus:**
  - Focused list row: `list_active` plus a 1px `primary` border (sidebar) or a 2px `primary` left bar (transcript). The tint alone is not visible enough.
  - Inputs and buttons use gpui-kit's `ring`.
- **Hover:** a background step (`list_hover` / `sidebar_accent` / `secondary_hover`) or, for tabs, text color. Never the only way to discover something.
- **Disabled:** `muted_foreground` text and the component's `.disabled(true)`; no hover; not focusable.
- **Motion:** none beyond `Spinner` and gpui-kit's built-ins. No custom animations or entrance effects (the palette uses `DialogEntrance::None`).
- **Selection:** text selection is translucent indigo (`selection.background`); keep it translucent so selected text stays readable.

## Components to reuse
| Need | Use |
|---|---|
| Keyboard hint | `Kbd::new(Keystroke::parse("cmd-k").unwrap())`, one chip per key of a chord |
| Command palette entry | A row in `COMMANDS` in `src/app.rs`: label, `IconName`, handler |
| Dialog with a form | `window.open_dialog` with a small `Render` entity (see `NewWorkspaceForm`) |
| Right-click menu | `Shark::show_menu` with `menu::item(..)`, `menu::sub(..)`, `Entry::Sep`; see `ws_menu` |
| Multi-select from a list | `Command` embedded in the form, items `.checked(..)`, `on_confirm` toggles (see `NewWorkspaceForm`) |
| Destructive confirm | `window.open_alert_dialog`, `ButtonVariant::Danger` |
| Feedback | `window.push_notification(Notification::success/error(..))`. No custom toasts |
| Text input | `Input` / `Textarea`; inside a card use `.appearance(false)` and let the card draw the border |
| Markdown | `TextView` + `TextViewState::markdown` |
| Primary action | `Button::new(..).primary()`, at most one per view |
| Row action button | `Button::new(..).ghost().xsmall()` with an icon only, shown on the row |

## Copy and destructive actions
- **Confirm only when data is lost.** Archive doesn't confirm; force-archive does.
- **Confirm dialogs:**
  - Title `Verb {name}?`.
  - The description states the consequence.
  - `ok_text` is the verb; use `show_cancel(true)`.
- **Errors name the fix**, including the key when there is one: "Add a repo first (space r a)".
- **Progress notifications** end with an ellipsis: "Creating PRs…".

## Keyboard and focus
- **Focus handling:** every view that handles keys gets a `key_context(..)` and a `FocusHandle`.
- **Bindings** go in `bind_keys` in `src/main.rs`:
  - Add the new context to `NAV` so leader keys work in it.
  - For lists, also add it to `LIST` and handle `SelectNext/Prev/First/Last/Confirm`, plus `PageDown/PageUp` where the list scrolls. The sidebar currently doesn't handle `PageDown/PageUp`.
- **New global commands** need:
  - an `actions!` entry;
  - a leader binding `space <group> <key>` in `NAV`;
  - a `COMMANDS` row;
  - a menu-bar item where it fits;
  - a line in the README keys table.
- **Row actions** act on the cursor row of the focused list, otherwise on the open item (see `archive`). They get a single-key binding in the list's context plus a palette row.

## Gotchas
- **Unknown theme keys are silently ignored.** Copy key names from `ThemeConfigColors` in gpui-component's `theme/schema.rs` (the link color is `link`, not `link.foreground`). The `themes_parse` test checks the core keys; extend it when you rely on a new one.
- **`list.active.background` alpha is capped at 20%** by gpui-kit. Setting a higher alpha does nothing.
- **The `tab.*` theme keys are unused;** the tabs draw with `secondary` / `foreground` / `muted_foreground`.
- **`cx.theme()` borrows `cx`.** Copy the colors you need into locals before calling `cx.listener(..)` or other `&mut cx` methods (see the composer in `src/chat.rs`). Don't clone the whole `Theme` per render.

## Checklist for a UI change
1. Colors come from theme tokens (or `faint`), with no hex in views. Every new text pair meets the contrast rules.
2. Sizes, radii, type and icons come from the tables above. Status uses the status vocabulary.
3. The command is reachable by keyboard and listed in the palette and the README.
4. Dialogs apply `inter_features()`.
5. `cargo test --features test-support` passes (the headless keyboard test covers focus and key contexts).
6. Checked by eye in both modes, without changing the system appearance:
   ```sh
   ./target/debug/shark &                                         # follows the system (dark here)
   ./target/debug/shark -NSRequiresAquaSystemAppearance YES &     # forces light for this process
   screencapture -x -o -l <window-id> .context/shot.png           # window id: CGWindowListCopyWindowInfo, owner PID
   ```
